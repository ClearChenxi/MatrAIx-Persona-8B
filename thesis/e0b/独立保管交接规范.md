# T结果独立保管交接规范

状态：**尚未完成独立交接，正式T预测不得开始。** 当前证据仍是同一系统账户下的本地逻辑封存。本文增加前瞻性强隔离门槛，不改写2026-10-11已经发生的E0b运行，也不能事后证明执行者过去从未接触T结果。

## 为什么不能只移走T标签文件

`labels_T_SEALED.csv`不是唯一可恢复结果的对象。`coupon_redempt.csv`可以重建主标签Y1，`transaction_data.csv`可以重建辅助标签Y2，原始压缩包可以恢复全部源表。因此独立保管必须覆盖策略文件列出的五项对象；只加密派生T标签仍不构成独立隔离。

## 合格交接

独立保管人必须是实验执行者无法控制的个人或系统账户。保管人接收并核对五项对象的SHA-256承诺，以自己的GPG签名密钥签署回执；若使用加密传输或存储，解密私钥只能由保管人持有。执行账户随后不得再能读取五项明文，包括能恢复源表的本地压缩包。

回执只包含对象名、SHA-256、接收状态、保管人身份/角色、签名公钥指纹、接收时间和固定释放条件，不包含标签值、正例数或响应率。格式模板见`custody-receipt.template.json`。签名回执及其分离签名可以进入Git；受保护明文、密文和密钥均不得进入Git。

固定释放条件为：全部冻结的E1/E1a预测，以及获批时全部E2预算预测，均已提交、推送并登记哈希。释放应由保管人执行评价或在该条件满足后才返还标签；不得提前向实验执行者提供逐户标签或结果摘要。

## 自动门槛

政策见`custody-policy.json`，核验器见`verify_custody.py`。核验器不打开受保护对象，只核对公开承诺、保管人签名及执行账户是否仍能读取明文：

```sh
.venv/bin/python thesis/e0b/verify_custody.py \
  thesis/e0b/runs/e0b-20261011T033848.685233Z \
  /path/to/custody-receipt.json \
  /path/to/custody-receipt.json.asc
```

只有输出`independent_custody_verified`时，才可把独立保管状态记为完成。原E0b证据完整性核验应在交接前完成；交接后受保护明文不可访问是预期状态，改由本核验器检查公开承诺、签名和不可读性。当前没有独立保管人签名回执，且五项明文仍可由执行账户读取，所以该门槛预期失败。
