# E1b 探索扩展：Persona 1M 多候选汇总辅助家庭预测（设计草案）

状态：**待实验设计者和用户审核；不是已冻结协议，不授权用候选人物运行模型或进入 T。** 本草案依据[字段可配对性审计](可配对性审计-20261014.md)、现行研究蓝图与执行手册。用户已决定：保留原 P1 及其失败记录；新增条件只用于离线论文评价，不作实际家庭定向投放；使用多个候选 Persona 的汇总，不把库中某人称作 Dunnhumby 家庭本人。

2026-10-14 状态更新：用户另行授权了**只读全量来源覆盖审计**，已完成并记录在[全量覆盖审计](全量覆盖审计-20261014.md)。固定版本文件已在本地下载，但**仍未授权将候选人物接入模型或开展新条件的预测试跑**。四个购物字段同时齐全的 400,745 条中，400,000 条为合成来源。用户因此确认：首个探索条件只要求“购物风格＋节俭倾向”两字段，以**非合成来源**为主体；合成人物另列敏感性条件，不合并为一个代表性群体。两字段非缺失的非合成记录为 6,552 条，但其中两字段都可按官方类别直接解码的只有 **3,378 条**（Wiki 1,424、Amazon 1,637、真人问卷 314、PRISM 1、Stack Overflow 2、GSS 0）；是否以此为正式候选池待用户确认。这些是来源于真实记录的*人物构造*，不能称为属性全部经真人验证。

## 1. 要回答的新增问题与不能回答的事

新增问题是：在**相同的 Dunnhumby 家庭—活动记录**和同一基础模型、同一预测事件下，加入 Persona 1M 导出的、不确定的**候选群体汇总**，是否比原 P1 及预算相当的对照，在历史 R 和后来预先固定的评价范围内改善兑换概率排序与误差？它是单独的探索条件，不是 P1 的更名或原 E1b 机制比较的组成部分。现有 P1 的 D20/R100 技术失败不因扩展获得好结果而消失。

没有与 Dunnhumby 家庭相连的 Persona 1M 身份标签或共同测量。若候选汇总按家庭 X 选择，它是 X 与外部人物库的预先固定函数，**不构成已验证的家庭心理、真实人口信息或新获得的个体标签**。若提高预测，最多说明这个外部汇总/表示方式在这批离线记录上有用；不能直接断定真实人格匹配、营销增量、投放收益或跨活动推广。

## 2. 候选的最小安全表示

- 每个家庭—活动在预测开始日之前的 X/S 来自已冻结的 56 字段输入，不使用家庭 ID、活动 ID、当前活动 Y、T 结果或未来交易进行候选选择。行键只能在本地用于可复现哈希和日志。
- 拟在用户确认后，从固定版本 Persona 1M 的**非合成、两字段均可按官方类别解码**候选池抽取若干候选，记录完整来源修订、抽样 seed、候选索引哈希与缺失率。合成来源用同样两字段另做敏感性条件。**不向模型展示单个人物的姓名、原始描述、原始证据、来源记录 ID 或完整人物档案。** 只汇总这两个预定属性的类别计数/比例及缺失比例，且写明“假设性外部候选分布，并非该家庭的属性”。不加入年龄、性别、地区、种族、收入等敏感或未经家庭侧验证的身份字段。
- 候选人数 K、来源内抽样权重、汇总精度、无候选回退、是否允许同一人物重复被抽取，均须**在提取候选池或 D/R 模型试跑前**确定。若某真人来源的描述或上游限制与离线家庭级任务不兼容，应在设计审核阶段限制来源或停止；不得以仓库 MIT 许可替代数据集非商业研究许可。
- 多候选汇总将作为额外上下文进入**同一个家庭 Persona Agent 工作流**；模型调用仍以家庭—活动为单位，而不是把候选人物分别当作真实家庭成员去运行。若之后要逐人物运行并平均分数，那是另一方法，必须另行设计、预算和命名。

## 3. 必须成对的条件（拟议，尚未冻结）

| 条件 | 给模型的新增内容 | 必须回答的区别 |
|---|---|---|
| 原 P1 | 无；保留此前代码与失败审计 | 原方法基线，不以新运行覆盖旧失败 |
| E-1M-C（非合成候选汇总） | 由 D 阶段预定的 X→候选权重/筛选规则导出的两字段群体汇总 | 外部汇总与特定 X 的预设关联是否可能有用 |
| E-1M-PERM（打乱关联） | 完全相同格式和非合成候选来源，但在同活动家庭间以固定哈希置换汇总 | 区分“有关联的汇总”和仅多一段外部文本 |
| E-1M-X（X 映射对照） | 只呈现同一 X 的匹配/分箱变量，不提供 Persona 1M 分布；长度与格式尽量匹配 | 区分人物库带来的价值与重新解释已有 X 的价值 |
| E-1M-SYN（合成来源敏感性） | 两字段均有值的合成人物候选汇总，与非合成条件使用同一规则 | 检查方向是否依赖来源；不与非合成条件合并增样本 |

这些条件须共用评价家庭、活动、任务语义、模型、输出 schema、生成参数、技术失败与回退规则。需要预先说明 E-1M-C 相对 E-1M-PERM、E-1M-X 的主比较，以及相对原 P1 的描述性差；不得选择最有利的一项改称“Persona 1M 提升质量”。置换不得泄露另一家庭的原始记录或标签；只交换已生成的匿名汇总。

**注意：** 目前没有经验证的 `购物篮数/用券比例 → 购物风格` 或 `消费金额/折扣比例 → 节俭程度` 对照表。任何筛选或权重都是待检验的代理假设，必须在 D 定义、R 评估，并在论文中如此标注；不能称为“真实匹配”。若设计者无法给出可辩护的规则，E-1M-C 不执行，不可把随机群体总结伪装成家庭特异性预测。

## 4. 分阶段退出条件

1. **设计与许可门槛：** 确认仅非商业研究、无实际个人定向应用；定稿来源内抽样比例、候选 K、属性与缺失政策、代理映射、扩展条件的预算与结论边界。修订蓝图/手册并保存原方案和变更理由。
2. **人物库可行性：已完成覆盖审计。** 固定修订的完整 999,847 条已经下载并逐分片核验；两字段非合成候选池的规模与来源构成已查明。仍须核对最终抽样规则不会把极小来源过度放大。样本 viewer 的 999 行和仓库的 200 条开发样例不代表完整库。
3. **D/R 方法开发：** 先实现本地可复现的候选选择器、汇总器与匿名日志；以合成测试证明候选和评分绝不读取 Y，且置换仅改变候选汇总。每个执行版本先提交并推送 GitHub；原始人物与家庭逐条材料仅本地保存。随后在预设 D/R 行上做技术合法率、区分度、耗时与必要的历史预测检查。P1 的既有技术失败单独报告。
4. **扩展冻结或停机：** 只有独立方法、配对对照、资源上限、评价家庭和指标全部冻结，且技术门槛通过，才能考虑扩展的 T 预测。旧 T 曾解封参与旧实验校准，故即使工程上重新封存，结果仍应标记回溯、探索性；原 E1/E2 的主协议不能被这项扩展静默替换。

## 5. 当前仍需明确的设计决策

1. 用户已选择对合格非合成候选**按来源原比例抽样**，不强制等额；但需确认“合格候选”采用两字段可直接解码的 3,378 条，还是先为 3,174 条标准类别表外覆盖值单独设计映射。前者可避免无依据的映射，且改变先前 6,552 条的来源比例。
2. 每条家庭—活动候选 K 与汇总稳定性复核规模。K 改变计算量与分布精度，不能看 R 表现后任意加大。
3. 用户已选择预先固定**弱代理加权**，并保留打乱关联与 X 重述对照；还需确定具体、可证伪的 X→候选权重规则：用哪几个交易字段、如何分箱、映射到哪两个 Persona 1M 属性，以及软权重上限和零支持时的回退。尚无经验证的心理映射，不能称为真实匹配。
4. 扩展条件的主历史指标、配对报告方式和计算时间/本地存储上限。不得把“分数不再集中”本身写成真实兑换预测改善。

目前这些设计空位未被用户或设计者确认，因此**不执行人物抽样、代理映射、模型试跑或 T 预测**。
