# 毕业论文实验蓝图：MatrAIx Persona Agent 与传统营销评估方法

版本：v0.4 · 日期：2026-10-11

状态：论文级研究蓝图。E0a、E0b 与统一 D/R/T 输入整理已经完成；**尚未运行任何正式 T 预测。下文的指标、表和图仍是预注册式计划产物，不是实验结果。**

逐步操作、输入与产出、验收条件及执行交接见 [实验执行手册](实验执行手册.md)。E0a、E0b 及统一 D/R/T 输入已经由日期化材料验收；测试活动重叠的推断限制也已确认。E1a/E1b 的具体方法、提示、模型、随机性、失败处理和 E2 小标签预算仍须在正式 T 预测前完成 D/R 开发并冻结，不能把计划指标、表图或方法清单误写成实验结果。

本版本替代 v0.1 中“以 Hillstrom 冷启动邮件匹配为唯一主实验”的定位。调整原因很直接：本论文要比较的是 **MatrAIx Persona Agent 与传统营销评估方法**，不是比较男装邮件和女装邮件本身。营销方案是所有方法共同面对的输入；Persona Agent、规则和传统模型才是实验变量。

## 1. 论文究竟要主张什么

### 1.1 核心研究问题

> 在营销活动正式投放前，当各方法只能使用投放前客户信息和活动描述时，所评估的 Persona Agent 配置能否对留出真实客户响应形成外部有效的预测；它是否比 RFM 规则及传统监督学习模型更有竞争力；观察到的差异是否确实来自 Persona 信息、表达或 Agent 工作流，而不是一般 LLM 能力或无关的活动常识？

这里的“方案”可以是一项已经定义好的优惠券/促销活动，而不是研究要比较的对象。在 Dunnhumby 主实验中，它被严格定义为一项 **Type B 或 Type C 活动中的优惠券包**：已知其覆盖的商品/品类/品牌、有效期和活动规则，并且参与家庭均收到该活动的完整优惠券包。所有方法都获得同一份活动描述和同一时点可见的客户资料，然后分别输出“该客户或客户群体的响应分数”。

论文不预设 Persona Agent 会胜出。若传统模型在相同信息约束下更准确，应如实将其作为主结果。

### 1.2 四个研究层次

全文保留四个递进层次，不能把当前实施范围误写成只有三个层次：

| 层次 | 真正的问题 | 所需证据 | 当前归属 |
|---|---|---|---|
| 1. 预测有效 | Persona 分数是否包含真实响应信息？ | P1 相对无个体预测基准的排序富集与概率误差 | E1a |
| 2. 相对更好 | Persona 是否比现有方法更有用？ | P1 相对 RFM、Logistic、CatBoost 的同样本比较 | E1a |
| 3. Persona 有价值 | 差异是否来自 Persona，而非一般 LLM 能力？ | 同模型、同 X/S 的结构化直估、Persona 直估、Agent 与错配/精简对照 | E1b |
| 4. 活动—人群匹配 | 模型是否知道“什么活动适合什么人”？ | X+S 相对仅 X、正确活动相对错配活动及交互证据 | 暂缓设计，不由 E1a/E1b 代答 |

E1 是当前第一个核心实验的父级名称，不额外产生一套预测。E1a 与 E1b 是其两个子实验。第四层仍属于总体研究框架，但本版本不新增对应实验实体；待后续单独讨论识别条件与数据后再冻结。

### 1.3 正确的比较单元

| 固定不变的条件 | 要比较的方法 |
|---|---|
| 同一活动描述 S、同一投放前客户信息 X、同一预测时点、同一留出真人结果 Y、同一测试客户集合 | P1：MatrAIx Persona Agent 或经严格说明的兼容领域 Persona Agent |
|  | B1：RFM/业务分群规则 |
|  | B2：Logistic 回归 |
|  | B3：CatBoost 等强表格监督模型 |
|  | E1a-N0/N1：冻结历史常数与仅活动基准 |
|  | E1b-L0/L1/L2：活动-only、结构化直估与 Persona 文本直估 |
|  | E1b-P2/P3/P4：错配、精简与第二模型复核 |

因此，不能把“男装邮件 vs 女装邮件”写成 Persona Agent 的对照组，也不能拿不同方法各自选择的方案、不同用户资料或不同测试集来比较。

### 1.4 预测、机制与决策结论不能混用

1. **响应预测层**：分数是否包含真实响应信息，以及相对预设传统方法是否更好，由 E1a 回答。
2. **Persona 机制层**：相同基础模型和相同事实下，Persona 表达、Agent 工作流、正确画像关联及丰富行为字段是否有附加价值，由 E1b 回答。
3. **活动匹配与投放决策层**：是否应向某人投放某项活动，需要额外的活动特异性或随机对照证据；当前 E1a/E1b 不回答该问题。

预测准确不自动等于能提高投放收益；随机实验中的策略收益也不自动等于销售利润。论文必须分别报告。

## 2. MatrAIx 的产品逻辑与本论文的缺口

MatrAIx 的产品范式是：固定一个被评估的产品或任务，指定 Persona cohort、用户场景和结果指标，让 Persona Agent 在 Survey、AI Chatbot、Web 或 App 环境中完成任务，再分析总体和子群体结果。其公开技术报告中的营销相关例子包括购买意向、价格敏感性、留存与推荐等任务。

公开验证主要检验任务执行、Persona 属性遵循、跨 agent 模型的群体模式和 Persona 来源质量。它**没有**给出“Persona Agent 在真实营销客户响应预测上优于 Logistic/CatBoost/RFM”的直接结论；报告还明确指出，模拟结果受 persona-agent 模型影响，涉及真实人群的结论需要用同一任务上的真人数据验证。

这正是本论文的研究缺口：在一个固定营销任务中，将 Persona Agent 和传统方法放在完全相同的信息、时间与真实结果约束下比较。

参考：[MatrAIx 技术报告](https://arxiv.org/abs/2608.04205)，尤其是任务定义、验证和限制部分；[Applications 页面](https://matraix.ai/applications/)。

## 3. 方法命名与接入门槛

“MatrAIx Persona Agent”是需要被核实的产品称谓，不能因为提示词风格相似就直接使用。正式实施前先完成下表的 E0a。

| 实际能力 | 论文中的准确名称 | 可以声称什么 |
|---|---|---|
| 可调用官方 MatrAIx Persona/Agent，能保存官方 cohort、任务、agent、模型和 seed 配置 | **MatrAIx Persona Agent** | 比较该官方配置与传统方法 |
| 只能用公开零售字段构建结构化画像，再调用普通 LLM | **MatrAIx-compatible domain persona agent** | 比较本地领域 Persona 方法与传统方法，不能代表官方产品性能 |
| 只有无画像通用 LLM | **LLM 对照** | 检验一般语言模型，不是 Persona Agent |

无论采用哪一种，Persona 中的字段必须来自数据在预测时点前的直接记录或明确聚合。交易频率、购买品类、优惠券使用率可以作为行为 Persona；不能从中编造性格、收入、动机或受保护属性。每个字段保留来源列、时间窗口、聚合规则和缺失状态。

## 4. 数据角色与选择结论

| 数据 | 论文角色 | 优点 | 关键边界 |
|---|---|---|---|
| **Dunnhumby The Complete Journey** | **主实验 E1/E2** | 两年家庭交易历史、活动与优惠券信息、优惠券兑换、活动后交易；可构造丰富且有时间顺序的交易行为 Persona | 活动分配机制未确认随机；不能将预测结果写成因果增量或利润因果效应 |
| **Hillstrom 邮件实验** | 次实验 E3：随机化策略压力测试 | 邮件/无邮件随机分配，后续访问、购买、消费结果可用于离线策略评价 | 用户特征稀疏，邮件无正文、价格或折扣；只检验简化邮件类别场景，不能单独证明完整 Persona Agent 的营销能力 |
| UCI In-Vehicle Coupon | 可选附录 E4 | 有较丰富的人口与消费习惯字段、优惠券情境和接受选择 | 问卷意愿而非真实购买，非随机投放；不作为主结论证据 |

**结论**：Hillstrom 不是最好的唯一主数据。它保留为因果识别较强、但 Persona/方案语义较弱的稳健性检查。Dunnhumby 更贴近 Persona Agent 上线前评估“某项零售活动会吸引谁”的产品场景，因此承担真实响应预测的主实验。

本地 Dunnhumby 审计已指出：Type A 活动不能观察每个家庭实际收到哪 16 张券；因此 E1/E2 只在确认收券关系的 Type B/Type C 活动上实施。分析总体是 `campaign_table` 中该活动的参与家庭，不是全体家庭；具体字段和授权限制见 [Dunnhumby 审计](../feasibility/DUNNHUMBY_AUDIT.md)。

## 6. E0：开始前必须完成的审计

### 6.1 E0a：产品与配置审计

产出一份不可修改的 `agent_manifest`，至少包含：方法名称、官方或兼容状态、Persona 来源、cohort 抽样方法、任务模板、agent/LLM 精确 ID、模型版本、温度、seed、输出 schema、调用日期、每个样本的原始响应和解析状态。

若使用官方 MatrAIx，必须保存官方可导出的任务与 cohort 标识；若不可保存或无法证明调用了官方产品，不得在摘要、图表或结论中用“MatrAIx 产品优于传统方法”的表述。

### 6.2 E0b：Dunnhumby 数据与事件审计

以活动开始日 `START_DAY` 为预测截点，构造家庭-活动单位 `(household_key, campaign)`，且仅保留 `campaign_table` 中 Type B/C 的参与家庭：

- `X`：开始日前的交易、品类偏好、消费频率、最近购买、折扣/优惠券使用率及允许使用的匿名家庭字段；
- `S`：活动类型、有效期、可确认的优惠券商品/类别/品牌与已知活动规则。为使未见活动可泛化，`S` 必须预先编码为可跨活动复用的部门/类别/品牌族、券包规模和时长等特征；不得把测试活动的兑换率、逐户结果或不可复用的活动 ID 当作特征；
- `Y1`（**主标签**）：活动期是否兑换该活动的任一已确认优惠券；
- `Y2`（次标签）：活动期是否购买目标商品/类别；
- `Y3`（次标签）：活动期目标商品/类别的消费金额。

审计必须确认：客户在活动开始前有足够历史、Type B/C 的收券关系可识别、活动期结果不进入画像、重叠活动的处理规则、活动和家庭数量、各结果基率、缺失和重复行。对于相互重叠的活动，任一家庭在活动 c 的 X 只能使用 `START_DAY(c)` 之前已结束或已发生的记录，不能借入 c 或其后的结果。匿名 `classification_*` 不翻译为年龄或收入。

初始静态核查发现 19 个 Type B、6 个 Type C 活动，共 3,229 个家庭—活动观察；后续 E0b 和统一输入验收已经固定 D=729、R=681、T=1,714 条，并排除结果窗不完整的活动 24。最终 T 的 10 个活动属于同一个时间重叠连通块，因此 E1 的跨活动证据固定为探索性，不能以家庭行数替代独立活动重复数，也不能事后升级为确认性外推。

主实验按时间划分，不能随机打散未来和过去：用早期活动开发方法与超参数，中间一段活动作适配/验证，最后一段预先指定的未来活动作锁定测试。若活动总数或 Type B/C 数量不足以支持稳定的时间留出，则暂停主实验，不能用随机行切分伪造“投放前”场景。

**E0 的结论仅是可行性与精度**，不是方法优劣。Dunnhumby 的分配机制不明，因此 E0 不能把不同家庭的响应差异解释为活动造成的增量。

## 7. E1：未来活动响应预测父实验

E1 统一使用同一 D/R/T、同一主标签 Y1、同一测试家庭和活动，由 E1a 与 E1b 两个子实验构成。E1 不另行生成第三套分数，也不把两个子实验中较有利的结果拼成一个胜负结论。

### 7.1 共同任务

对尚未解封结果的未来活动 c，各方法仅使用活动开始前的家庭行为 X 与活动事实 S，预测已确认收到该活动完整券包的家庭 i 是否会在有效期内至少兑换一张合法券。Y1 为唯一主标签；Y2/Y3 只作预先指定的辅助结果，不能替换不佳的 Y1。

P1 仍指 E0a 已验收身份的 `MatrAIx-compatible domain persona agent（基于官方开源 Survey Agent，本地 Qwen 后端）`，不能简称为官方托管产品或 Persona-8B 模型。所有测试结果在方法、提示、随机性、校准和失败规则冻结后才解封。

### 7.2 E1a：预测效度与传统方法竞争力

| ID | 方法 | 角色与输出 |
|---|---|---|
| N0 | 在 D 冻结的总体历史兑换率 | 所有记录同一概率；无个体、无活动差异的最低概率基准 |
| N1 | 仅使用 S 的活动级概率模型 | 不使用家庭 X；同一活动内分数相同，只评价活动层概率信息，不宣称个体排序 |
| B1 | RFM 与历史兑换规则 | 确定性排序分数；不参加概率校准评价 |
| B2 | Logistic，使用同一结构化 X/S | 历史监督响应概率 |
| B3 | CatBoost，使用同一结构化 X/S | 强表格监督响应概率 |
| P1 | 完整 Persona Agent，使用同一事实范围 X/S | 原始声明概率及冻结的 R 校准版本 |

层次 1 的主问题是 P1 是否包含外部预测信息。评价包括：P1 相对 N0/N1 的逐活动 AP、相对活动实际正例比例的 top-k 富集，以及 P1 相对 N0/N1 的 Brier/log loss。测试活动实际正例比例只在解封后作为评价参考，不允许成为预测输入。

层次 2 的主问题是 P1 是否比现有方法更有竞争力。主排序比较族固定为 `P1-B1`、`P1-B2`、`P1-B3` 的逐活动 AP 差；概率比较只在 P1、N0、N1、B2、B3 之间进行。AP、概率准确性和 top-k 富集分别作答，不能用多个指标投票决定胜负。

结果必须分级陈述：P1 未胜过 N0/N1 时不能声称有可用外部预测信号；只胜过 B1 时只能称优于简单规则；未胜过 B3 时不能概括为优于传统方法；AP 更好但 Brier 更差时只能称排序改善、概率失准。

### 7.3 E1b：Persona 增量价值与机制

E1b 与 E1a 使用完全相同的评价行、活动、Y1、基础模型版本和输出事件。除预设改变因素外，数值精度、字段顺序、任务语义、最大输出和失败处理保持一致。

| ID | 条件 | 唯一有意差异 | 可以回答的问题 |
|---|---|---|---|
| L0 | 活动-only 直接 LLM | 只给 S，不给家庭 X，不使用 Agent 工作流 | 客户事实整体是否提供价值 |
| L1 | 结构化事实直接 LLM | 完整 X/S，以中性结构化格式直接估计概率 | 普通 LLM 使用相同事实能做到什么 |
| L2 | Persona 文本直接 LLM | 与 L1 相同事实，改为冻结 Persona 文本；不使用 Agent 工作流 | Persona 表达相对结构化表达是否有价值 |
| P1 | 完整 Persona Agent | 与 L2 相同事实和 Persona 文本，使用官方开源 Survey Agent 工作流 | Agent 工作流相对直接 LLM 是否有价值 |
| P2 | 错配 Persona Agent | 活动 S 与原 Y 不变，将整套家庭 X 跨预设行为群体置换 | 正确客户—画像关联是否有价值 |
| P3 | 精简 Persona Agent | 只保留冻结的 R/F/M 基本行为与同一 S | 丰富行为画像是否有增量价值 |
| P4 | 第二模型复核 | 在相同输入、条件和任务上更换预设基础模型 | 方向是否依赖单一基础模型 |

主要机制对比固定为：`L1-L0` 检验客户信息，`L2-L1` 检验 Persona 表达，`P1-L2` 检验 Agent 工作流，`P1-P2` 检验正确关联，`P1-P3` 检验丰富画像。P1 相对 L1 的总体差另行报告，但不能代替上述分解。

只有 P1 优于 L1 且正确关联对照 P2 明显退化，才能支持“完整 Persona Agent 相对普通 LLM 直接估计具有增量价值”。只有 `L2>L1` 才能把差异归于 Persona 表达；只有 `P1>L2` 才能把差异归于 Agent 工作流。P1 仅优于 L0 只说明客户信息有用。第二模型方向反转时，结论必须限定为当前基础模型配置。

E1b 属于预设机制实验，不通过从多项对比中选择唯一显著者来声称 Persona 全面有效。生成理由只可作为案例材料，不能证明家庭真实心理或动机。

### 7.4 E1 的共同评价与结论边界

主排序指标为 Y1 的逐活动 Average Precision 等权宏平均；同时完整报告每活动结果、家庭数加权结果、top 10%/20%/30%、Brier、log loss、校准与失败率。当前 T 仅一个活动时间重叠连通块，主证据是这批未来时段活动中的探索性比较，不能生成伪独立的跨活动确认性结论。

E1a/E1b 可以支持已收券家庭中的响应预测与机制结论，不能支持活动造成的增量、最佳发券对象、利润、ROI、替代真实试验或第四层的活动—人群匹配结论。

## 8. E2：少标签条件下的 Persona 增量与数据效率

E2 是计划内应用实验，不是可按 E1 结果决定是否执行的补救分析。它检验：在相同少量目标活动标签下，冻结 P1 分数能否为传统 B3 提供额外预测信息，从而提高标签使用效率。完整活动期标签在 END_DAY 前不可知，因此它仍是回溯式少标签检验，不能证明真实上线前试投收益，也不对应第四层活动—人群匹配。

适配/最终评价家庭保持 E0b 已冻结的全局隔离。E1a 与 E1b 全部预测先封存，E2 再开放适配标签。权限计数在不读取 Y 的情况下已经确定：主分析固定活动 14、16、17、19、20、22、23、25，使用共同可执行的 `n ∈ {0, 10, 20}`；活动 20、22、23、25 另做 `n=40` 敏感性分析。活动 15 和 21 因适配池分别只有 2 和 18 条，不进入 E2 主学习曲线，但继续完整保留在 E1。

每活动按与 Y 无关的固定哈希顺序建立嵌套训练/验证子池，训练与验证标签全部计入 n，不能从最终评价家庭补样本。`n=40` 的四活动结果单列，不能与八活动的 `n=10/20` 连成同一条学习曲线。

每个 n 下比较；其中 n=0 只保留冻结历史参照，后三项仅在 n>0 时拟合：

- 冻结的历史 B3，不使用当前活动标签；
- 使用同一 n 个标签对历史 B3 分数进行低容量一维适配；
- 在相同适配框架和标签预算下加入冻结 P1 分数；
- 在相同框架下改为加入冻结 B2 分数，检验 Persona 分数是否超过传统预测源融合。

所有当前活动标签，无论用于训练、验证、校准还是失效检查，都从 n 中扣除。主比较固定为 E2-2 相对 E2-1 的八活动等权宏 Brier 差；负值表示加入冻结 P1 后概率误差更低。E2-2 相对 E2-3 检验 P1 是否超过增加另一个传统预测源。log loss、逐活动差、AP 和 top-k 作为补充，不能以其中较有利的指标替换宏 Brier 主结果。

E2 必须报告，包括单类标签、拟合失败、完全分离或回退；这些情况不能成为结果可见后取消 E2 的理由。若 E2-2 在 n=10 和 n=20 均降低宏 Brier，可支持冻结 P1 在当前少标签范围内具有稳定的增量信息；仅一个预算改善时只报告预算特异结果。若仅 E2 有益，论文结论必须限定为“少量目标活动标签开放后的辅助价值”，不能声称零标签 Persona 评估优于传统预测。

## 9. E3：Hillstrom 的随机化策略压力测试

Hillstrom 不是主预测数据，而是对 E1 排序逻辑的**高内部有效性补充**。其用户资料只有历史消费、购买类别、地区/渠道等，方案也只有男装邮件、女装邮件、不发邮件，缺少正文、价格和折扣。因此它只测试稀疏行为画像下的方法表现。

将每种方法用同一投放前 X 和方案类别输出“发送邮件的预期响应分数”，在冻结测试集按固定预算（10%、20%、30%）选择客户。比较 RFM 规则、Logistic/CatBoost、P1、同信息直接 LLM 和“不发邮件”策略。若随机分配机制与处理概率经 E0 审计确认，使用 IPS/SNIPS 估计各固定策略的两周访问率并以客户配对 Bootstrap 计算差值区间。

| 产物 | 允许回答的问题 | 不能回答的问题 |
|---|---|---|
| 表 5：各预算下的策略价值、覆盖率、相对不投放差 | 在此随机邮件试验中，各方法的排序能否形成较高的估计访问率？ | 具体文案、价格或优惠券设计是否更好；完整 Persona Agent 是否在所有营销任务中有效 |
| 图 4：预算-价值曲线与策略重叠 | 方法差异是否只发生在某一预算或某些客户？ | 实际利润、长期留存或未来跨市场效果 |

E3 有益会增强“预测排序具有决策相关性”的证据；E3 无益不会自动推翻 E1 的响应预测结论，只说明不能在这一稀疏邮件场景中支持策略优势。反之，E3 不能替代 E1，因为它没有足够的方案语义来代表 Persona Agent 的主要产品能力。

## 10. E4：可选的问卷泛化实验

若时间与资源允许，在 UCI In-Vehicle Coupon 上按优惠券类型留出，比较 P1、无 Persona LLM、Logistic 和 CatBoost 对“接受优惠券”问卷结果的 Brier、AUC 和群体误差。它只说明未见券类型的**问卷接受预测**；不能证明购买、兑换、增量销售或投放策略价值。

E4 只有在 E1 完成后才执行，且无论结果好坏都不能改变主结论。

## 12. 实施顺序与协议冻结

审查结论：**本设计可以用于“已确认收券家庭的活动响应预测”研究。** 正式实施须同时采用[审查修订与实施补充](REVIEW_FIXES.md)，其中固定主指标 AP、比较族、时间边界、测试摘要封存、家庭依赖、E2 回溯标签预算和 E3 固定覆盖率策略，避免将响应预测解释为完整方案因果效果或 ROI。

1. 完成 E0a：确认官方接入或将项目准确命名为兼容领域 Persona 方法。
2. 完成 E0b：审计 Dunnhumby Type B/C、活动时间线、结果定义与样本规模；无法形成可靠未来活动留出时暂停 E1。
3. 只用早期活动开发：确定特征窗口、Persona 字段、传统超参数、输出 JSON、活动划分、主指标、预算和失败回退。
4. 记录冻结版本：原始文件哈希、活动/家庭划分、代码版本、agent/model/cohort/task 配置、提示、种子、成本上限和主比较族。此时未来测试活动的结果仍不可读。
5. 运行并完整封存 E1a 与 E1b 的全部必需方法制品；再按冻结流程开放适配标签、运行并封存 E2 预测，之后一次性解封最终评价结果。
6. E3/E4 使用独立冻结流程，按预设顺序报告或说明未执行；不根据主结果删去不利对照或改换主实验。

旧版 Hillstrom 冷启动方案仍保存在 [历史实验协议](../feasibility/EXPERIMENT_SPEC.md)，但它不再是这份蓝图的主实施规范。新的代码与统计 spec 必须以本蓝图的 E0–E3 为基础另行冻结，尤其要补全 Dunnhumby 的时间划分、事件口径、活动数量、功效检查和实际 MatrAIx 接入方式。
