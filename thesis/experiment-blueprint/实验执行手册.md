# 毕业论文实验执行手册：从研究问题到可交付结果

版本：v1.1；日期：2026-10-11。

本文是实验设计与执行交接文档，不包含程序、命令或伪代码，也不代表已完成正式实验。适用依据是本目录的 [研究蓝图](README.md) 与 [审查实施补充](REVIEW_FIXES.md)。历史 Hillstrom 冷启动协议、OpinionQA 烟雾测试和短视频探索不作为当前主实验结果。

E0a、E0b 与步骤 11--14 的统一 D/R/T 输入已经完成验收；方法开发、E1a/E1b 正式预测、协议冻结与 T 评价尚未完成。本文中已经验收的事实与仍待执行的配置必须明确区分，任何新方法配置仍须在测试结果解封前完成 D/R 开发并签署冻结记录。

## 1. 我们最终交付什么

全文保留四个研究层次：预测是否有效、是否优于传统方法、增益是否来自 Persona、是否存在活动—人群匹配。当前 E1 只实施前三层；第四层保留但暂缓设计，不能由当前结果代答。

E1 是父实验，由两个子实验组成：E1a 检验预测效度与传统方法竞争力，对应层次 1、2；E1b 检验 Persona 信息、表达和 Agent 工作流的增量价值，对应层次 3。E1 不另产一套预测。

实验单位为“家庭—活动”，主结果为“活动期内是否兑换该活动至少一张有效优惠券”。每个方法对同一家庭、同一活动给出分数，再与同一真实结果对照。

主线按以下顺序完成：数据与方法身份审计 → 固定时间划分 → 构建统一输入 → 历史开发与稳定性试跑 → 冻结协议 → 保存 E1a 与 E1b 的全部预测 → 必要时执行标签预算扩展 → 解封结果 → 统计与论文写作。

最终至少交付六类证据：

| 交付物 | 必须能回答的问题 |
|---|---|
| 方法身份与配置档案 | 比较的是官方 MatrAIx，还是自建兼容方法？ |
| 活动清单、样本流与时间审计 | 哪些家庭确实收到券？预测时能看到哪些事实？ |
| 字段与活动事实字典 | 每条画像和活动描述从哪里来？ |
| 冻结协议与预测档案 | 看结果前究竟确定了什么、输出了什么？ |
| 完整指标、逐活动差值与失败记录 | Persona 在什么条件下有用或失效？ |
| 论文表图与结论边界 | 哪些结论被数据支持，哪些仍待验证？ |

## 2. 当前材料支持什么，哪些问题尚待解决

已具备：Dunnhumby 原始八张表、E0a 方法身份与接口检查、E0b 数据和标签封存审计、统一 D/R/T 输入及论文级实验蓝图。本地兼容方法的历史接口检查已经通过，但没有官方托管 MatrAIx 接入证明，也没有当前营销任务的正式 T 预测结果。

当前有四项直接影响执行的限制：

1. E0b 与统一输入已经固定 D=729、R=681、T=1,714 条家庭—活动记录；T 中 328 条属于 E2 适配权限、1,386 条属于最终评价权限，活动 24 因结果窗不完整固定排除。
2. 最晚一段活动长期重叠，无法直接把活动当独立重复来做普通活动 Bootstrap。默认主分析因此采用探索性定位，不能事后因显著结果升级证据等级。
3. 以单活动约 12—276 户的既有规模看，20% 适配池无法支持早期的 100—1000 户预算；当前候选预算已修订为 n=0、10、20、40，仍须在冻结时决定是否执行及每档可用活动。
4. E0a 历史接口检查中 20 户里 19 户的三次输出均为 0，另 1 户均为 0.45。它不构成性能结果，但表明 P1 存在分数退化风险，必须在 D/R 通过区分度启动门槛后才能进入 T。

**本手册的默认论文范围：E0、完整 E1a，以及 E1b 的必要机制条件；完成这些后，再按资源与可行性执行 E2/E3。** E4 暂不排入基本进度，避免辅助数据分散主线。

## 3. 分工和结果权限

以下是工作角色，不要求增加人员，也不要求并行代理。若只有一名执行者，应按阶段和文件权限完成交接，并记录结果的实际历史可见性。

| 角色 | 工作 | 可以读取 | 必须交付 |
|---|---|---|---|
| 方案制定与审核 | 固定问题、口径、对照、统计与变更规则 | 背景、X/S、历史开发结果 | 本手册、冻结记录、结论边界 |
| 数据保管 | 检查连接、形成标签、管理白名单与解封 | 原始表；审计所需标签 | 样本流、输入表、封存标签、异常表 |
| 实验实施 | 处理输入、训练传统方法、运行 Persona | D/R 允许标签；T 的 X/S | 方法配置、逐条预测、原始调用日志 |
| 统计评价 | 按冻结协议评价，不根据结果重选模型 | 解封后完整预测与标签 | 指标表、差值、区间、表图 |
| 论文整理 | 将发现映射到章节 | 已验收交付物 | 数据、方法、结果、讨论文本 |

测试结果封存包含逐户 Y、活动兑换率、正例数量、按方法分数分组后的真实率等；这些都不能用来选提示、阈值或测试活动。保管审计仅发布预设异常、缺失和一致性计数，不发布测试响应摘要。

公开数据无法消除模型预训练污染；流程封存也不能抹去执行者此前已看过的结果。需记录谁在什么时候看过哪些结果。若测试活动的详细表现曾参与开发，应重新设计未用于开发的评价，或明确标注回溯探索性研究。

## 4. 阶段一：确认方法身份和最小任务（E0a）

### 步骤 1：整理既有工作，不混用结果

操作：将资料分为当前主设计、数据事实、历史探索、技术试跑四类。保留原文件，列出文档日期与适用范围。确认当前主实验是 Dunnhumby，不沿用旧方案的实验编号与标签权限。

产出：《资料与版本索引》。验收：每份引用材料都有角色；论文没有把 OpinionQA 的解析成功率当作营销预测能力。

### 步骤 2：核实官方接入

操作：核查是否实际拥有可用的官方 Persona/Agent 运行接口，是否能导出 persona/cohort/task、模型版本、参数与原始响应。只查已有接入能力，不购买服务、不发送对外消息。用历史开发活动做少量接口检查，不接触测试标签。

产出：《方法身份记录》，只允许以下两条主路径：

| 核实情况 | 后续名称与实施 |
|---|---|
| 官方调用与配置能被证明，且能输入本研究的家庭行为事实 | P1 使用“所评估的 MatrAIx Persona Agent 配置” |
| 官方能力尚不可证明，普通 LLM 链路可用 | P1 使用“MatrAIx-compatible domain persona agent”，记录与官方的差异 |

官方系统若会自动补齐未观测心理或人口属性，需关闭补齐或保存并剔除这些字段；若无法控制，就不能作为同信息条件下的主比较方法。官方独享外部知识或不可导出状态时，应另列产品整体比较，不能把差异完全归因于 Persona。

验收：方法称谓、实际运行来源和可追溯日志一致。身份未核实不会阻止兼容方法研究，但会限制论文题目与产品结论。

### 步骤 3：固定唯一主任务与实验层级

操作：所有方法输出“已确认收到该券包的家庭，在完整活动有效期内至少兑换一次的分数”。同时固定 E1 为父实验、E1a 为预测效度与传统比较、E1b 为 Persona 机制实验。第四层活动—人群匹配继续记录为未解决问题，不在 E1a/E1b 中增加替代性结论。不要求生成购买理由来证明准确性；主实验也不要求预测利润。

产出：《任务定义卡》，包含四层研究框架、E1/E1a/E1b 层级、单位、预测截点、主标签、输出含义、方法列表、主指标及证据范围。

验收：没有方法在预测访问、另一方法在预测购买；家庭记录没有被解释成单个家庭成员。

## 5. 阶段二：建立样本、时间划分和标签封存（E0b）

### 步骤 4：登记原始文件并确认表角色

操作：保存来源、下载版本、文件校验值、行数、表头、字段类型和文件保管位置。原始表只读；衍生数据使用独立版本。UPC 按标识符处理，不因数字类型丢失前导位或发生科学记数法转换。

| 原始表 | 当前用途 | 是否进入主输入 |
|---|---|---|
| campaign_desc | 活动类型、开始日、结束日 | 是 |
| campaign_table | 家庭是否参与该活动 | 建立样本，不把 ID 作为预测特征 |
| coupon | 活动—券—商品关系 | 是，转成可复用活动与匹配特征 |
| product | 商品部门、品类、品牌类型 | 是 |
| transaction_data | 截点前行为；截点后辅助结果 | 前后权限严格分开 |
| coupon_redempt | 已结束历史活动行为；当前主标签 | 前后权限严格分开 |
| hh_demographic | 匿名静态属性 | 默认主分析排除，时间来源核实后才作敏感性分析 |
| causal_data | 店内展示和宣传单 | 默认排除：没有可靠逐户曝光，规模也不必要 |

产出：《原始数据登记表》。验收：每张表的用途、主键和时间角色清楚；不把原始数据作为公开论文附件重新分发。

### 步骤 5：确认活动和收券总体

操作：campaign_desc 与 campaign_table 按活动连接，只纳入 Type B/C。以去重后的家庭—活动建立母表，并核对两张表的类型是否一致。Type A 仅可提供已经结束的历史行为，不作为主预测目标。

检查：活动日期是否合法、家庭—活动重复是否存在、券是否确实属于该活动、商品是否能连接、主数据是否完整覆盖全部活动有效期。

产出：《活动可行性清单》，至少包含活动 ID、类型、日期、参与户数、券数、商品数、连接异常和观察完整性。测试活动的响应率暂不填入公开清单。

验收：未在参与表出现的家庭不会被当作该活动的未兑换负例。

### 步骤 6：预设时间划分

依据已读取的日期元数据，采用以下候选划分。数字是数据中的相对天数，不换算成未提供的真实日历日期。

| 集合 | 活动 ID | 开始日范围 | 最晚结束日 | 可做什么 |
|---|---|---:|---:|---|
| D 历史开发 | 27、28、29、1、2、3、4、5、6、7 | 237—398 | 432 | 字段、提示、超参数和异常规则开发 |
| R 历史验证 | 9、10、11、12 | 435—477 | 523 | 配置选择、校准与稳定性检查 |
| T 锁定测试 | 14、15、16、17、19、20、21、22、23、24、25 | 531—659 | 719 | 冻结后预测与最终评价 |

此划分满足 D 的完整标签在 R 开始前可用，D/R 的完整标签在最早 T 开始前可用。活动 13、18 等 Type A 不属于上述目标集合。

默认最终方法在最早测试活动第 531 天前训练与冻结，整个 T 段不更新参数、不校准、不读取 T 活动标签。后续测试活动的交易窗口随各自 START_DAY 前移，这些已经发生的交易是部署时可见的信息；但不将 T 段活动的逐活动兑换结果作为可供学习或历史兑换率计算的输入。D/R 等在第 531 天前已结束的活动可以提供历史响应信息。

这是一项预设的“整段测试结果封存”限制，应在论文中说明；其含义比允许滚动学习的实际部署更保守。若未来需要滚动更新，必须另做独立扩展，不能与本主结果混合。

产出：《活动划分表与标签权限表》。验收：每条活动完整结果都在相应历史训练时间之后可用；模型训练不借用仅开始早、尚未结束的活动。

### 步骤 7：正视活动依赖，确定证据等级

操作：只根据活动日期绘制活动条带图，按“有效期有交叠或相接”形成时间连通块；再根据家庭 ID 统计跨活动重复覆盖，不读取 Y。

候选 T 的连通关系已经能从元数据确认：14 与 15 重叠，15 的第 547—708 天覆盖或连接 16、17、19、20、21、22、23、24、25；24 延伸至第 719 天。因此 T 的 11 个活动组成一个时间重叠连通块。

**默认验收结论：允许开展未来时段的留出响应预测比较，但跨活动外推的推断为探索性。** 不进行把 11 个活动假定独立的普通 Bootstrap，不把家庭条数当作未来活动重复数。也不为了获得显著性而删除长 Type C 活动。

若希望论文提供确认性“跨未来活动优越性”结论，需要新增多个具有可辩护独立性的活动时期或另有可靠依赖模型与精度证据。当前数据不默认满足这一条件。排除 Type C 的 Type B 敏感性结果可以报告，但不能事后替代全体主结果。

产出：《活动依赖与推断范围说明》。验收：统计表中明确区分“这些活动中的家庭抽样不确定性”和“新活动的外推不确定性”。

### 步骤 8：固定历史覆盖及小活动规则

默认历史窗为 START_DAY 前 84 天，即 START_DAY−84 至 START_DAY−1；当天交易不进入画像。

纳入条件：活动窗完整可观察、此前 84 天位于数据覆盖范围、家庭历史窗内至少有一笔合法正购买。没有交易记录不等于文件缺失，但本主分析限定为有可构建行为画像的历史活跃家庭。排除理由只按 X、S 和观察覆盖决定。

不另按测试响应率筛活动。所有通过结构审计的活动均保留；最终评价家庭少于 20 户的活动标注低支持度，仍报告可算结果，不能静默删除。20 户只是展示与诊断提醒，不是已证明统计功效的标准。

主活动宏平均以 AP 可识别活动计算，报告分母和全部活动清单。无正例活动保留，但 AP 按既定规范标为不可识别；全为正例的活动 AP 可算但没有区分度，必须注释。任何此类处理均不得因某方法表现改变。

产出：《样本流》，按原始参与 → 去重 → Type B/C → 连接有效 → 历史覆盖 → 观察完整 → 最终权限划分逐步记录数量。验收：每项排除都能追溯，尚未公布测试正例数。

### 步骤 9：在全局家庭层面划分 E2 权限

仅当 E2 已在冻结前决定执行：测试活动中的家庭按全局 ID、固定种子 20261009 一次性划为约 20% 适配、80% 最终评价。同一家庭在所有 T 活动的权限相同，不能在活动 A 为适配、活动 B 为最终评价。

E1a、E1b、E2 共用这 80% 最终评价家庭；适配家庭不计入任何主评价。历史 D/R 可包含同一家庭：主问题是已有客户在未来活动的预测，不是新家庭泛化。历史训练和最终评价家庭有无交叠须报告。

若在冻结前决定不执行 E2，可将全部 T 家庭用于 E1a/E1b，必须记录这一选择。冻结后即使 E2 因资源终止，也不把原适配池并回最终评价来改善主结果。

产出：《家庭权限清单》。验收：权限全局一致、划分未按 Y 分层、测试评价集合不会随方法改变。

### 步骤 10：建立并封存标签

主标签 Y1：coupon_redempt 中同时匹配家庭、活动、有效 COUPON_UPC，且 START_DAY ≤ DAY ≤ END_DAY 的至少一条有效记录，记为 1；观察窗和日志完整但无有效记录，记为 0。重复兑换记录不重复计家庭响应。

异常处理：跨活动 UPC、券不在该活动、兑换日超期、无参与关系、未知家庭、非法日期分别计数。异常兑换不能被私自改成合法正例；无法确认完整标签的家庭—活动标为不可评价并保留原因。开发阶段确认统一规则后，保管方对所有集合一致执行。

辅助 Y2/Y3 默认定义：目标商品集合是预测前 coupon 与 product 固定连接得到的**精确 PRODUCT_ID 集合**。Y2 为活动期是否存在目标商品的合法正购买；Y3 为该集合活动期 SALES_VALUE 的记录净额，含可识别退货，不二次扣减折扣列。Y3 不是利润，也不是活动增量。品类级购买若执行，另列敏感性口径，不能替换精确商品标签。

如净额含义或退货识别尚无法核实，就暂不做 Y3；Y1 仍为唯一主结果。仅生成辅助标签不意味着已评价它们，概率预测与评价流程须另行预设。

产出：隔离的标签表、异常表、封存记录。验收：实验实施者只能读取允许的历史标签，不能读取 T 响应摘要。

## 6. 阶段三：将画像和活动转换成同信息输入

### 步骤 11：冻结字段字典

原则：所有方法的同信息版本由同一张家庭—活动结构化表生成；Persona 文字只做确定性呈现，不添加字段中没有的事实。家庭 ID、活动 ID 仅用于连接和日志，不作为特征，也不展示给 LLM。相对时间使用窗口天数与时长，不展示可直接索引公开活动结果的 ID。

| 字段组 | 建议主字段与定义 | 来源与处理 |
|---|---|---|
| R | 距最近一次合法正购买天数 | START_DAY 减窗口内最近 DAY；无购买不进入主样本 |
| F | 84 天购物篮数、购物天数 | 合法正购买的不同 BASKET_ID 与 DAY；不是交易行数 |
| M | 正购买 SALES_VALUE 合计、平均购物篮金额 | 仅正数量且非负金额记录；退货计数单列 |
| 折扣行为 | 含零售折扣的篮占比、含券折扣的篮占比 | 明确记录哪些折扣列非零及符号含义；不称心理价格敏感性 |
| 历史活动 | 历史完整参与活动数、已兑换活动数、两者比例 | 仅使用冻结权限允许且已结束的历史活动；分母为 0 时缺失 |
| 部门偏好 | 各部门支出占比 | 按正购买金额计算；数据不全不写“没有偏好” |
| 品类偏好 | 前 3 个 commodity 及各自支出占比、其余合计占比 | 先按 D 词表映射，再排序；传统模型和 Persona 都只使用这三个槽位及其余比例 |
| 品牌类型 | National、Private 等实际 BRAND 值支出占比 | 这是品牌类型，不是具体品牌名或忠诚度心理 |
| 活动属性 | 类型、有效天数、唯一券数、唯一商品数、部门/品类覆盖 | coupon/product/campaign_desc；时长 END−START+1 |
| 家庭—活动匹配 | 历史目标商品金额占比、目标品类金额占比、最近目标购买天数 | 先固定活动目标集合，再在历史交易中匹配 |
| 缺失与稀疏 | 无历史活动标志、商品类别缺失标志、历史记录数量 | 不把缺失统一解释为 0 |

coupon 的一行是券—商品关系，不能把行数当券数。每券可对应多个商品；活动摘要的品类权重默认按去重的券—品类关系计算，不按同券商品行数放大，也不使用实际兑换量加权。

活动主输入默认展示券—品类权重最高的前 8 类及权重、其余合计权重、完整覆盖品类数量；传统模型使用同一组槽位，不额外取得完整商品或品类列表。部门与品牌类型占比则以共同冻结词表完整呈现给双方。偏好和活动品类并列按固定类别名称顺序打破；所有文本数值按同一精度输出并用于传统主输入，避免数值精度不一致。目标商品与目标品类匹配比例在原始已知集合上计算后，同时提供给双方。

字段有证据覆盖但没有变化时保留诊断；明显恒定字段可在 D 阶段按预设规则移除。类别词表只用 D 拟合，R/T 新类别按冻结的其他/未知规则处理。相同原始活动事实也按同一词表进入主 Persona，不让主 Persona 独享传统模型未获得的细粒度商品语义。

若希望另测完整长文本商品描述的价值，作为“增加方案语义”的独立扩展，不能与严格同信息主比较混为一谈。

产出：《字段字典》，每字段列出名称、单位、来源、窗口、计算定义、缺失、非法值、传统编码、Persona 呈现。验收：任何文字都能回查来源；所有方法得到相同事实。

### 步骤 12：固定活动事实卡

每活动事实卡必须包含：Type B/C、有效天数、确认参与家庭获得完整券包、唯一券数、覆盖部门与主要品类、品牌类型覆盖、已知规则、未知信息。

必须明确：数据没有可靠券面折扣金额、文案、图片、最低消费条件时，写“未提供”，不根据名称生成促销话术，也不借测试期消费推算折扣。

产出：《活动事实卡集》及《同信息核对表》。验收：每项活动事实都可在预测前确认，不利用目标期结果反推方案。

### 步骤 13：形成 Persona 与人工抽查

每条 Persona 表示一个家庭的观测行为，按固定顺序列出数值、类别、窗口和缺失。允许写“过去 84 天有券折扣的篮占比为某值”；不写“精打细算”“性格保守”等未观测心理断言。

人工抽查建议：D 中按高/低频、有/无历史兑换、有/无目标类别购买组合选取约 20 条，并加入缺失和退货边界案例。由审核者分别检查原始记录、聚合值、Persona 文本与活动事实卡。

T 输入检查可以检查时间边界、缺失与连接，不能看 T 标签决定改写文本。抽查发现普遍字段错误时，冻结前修复并重新生成全部版本；冻结后按变更流程处理。

产出：《Persona 人工核验单》。验收：窗口外和活动当天记录没有进入历史；缺失没有被写成“不喜欢”；不存在凭空补全的属性。

### 步骤 14：冻结行为分群

为了回答“哪些群体误差更大”，默认保留三条单独的群体轴：F 的 D 分布 1/3、2/3 分位点形成低/中/高频；历史活动兑换率在有历史者中以 D 中位数分低/高，无历史另成一组；目标品类匹配比例以 D 的 1/3、2/3 分位点分低/中/高。临界值划入较低档，分位点重复时合并空档，不为凑三档按 ID 强分。记录实际阈值和档数。

不默认做三轴的全部交叉，以免样本过碎。每群体报告家庭—活动条数、独立家庭数、活动覆盖、预测均值、真实率与概率误差。少于 30 条时标注低支持度，不据此作方向性结论；正例/负例不足时不强算 AUC。

产出：《固定群体映射》。验收：阈值和合并规则在看 T 的真实率前确定，未通过错误最大的群体反向修改 Persona。

## 7. 阶段四：历史开发与方法落实

### 步骤 15：形成 E1a 的无个体基准与规则基线

N0 为只用 D 冻结的总体历史兑换率，所有未来记录输出同一概率。N0 不读取 R/T 基率，不产生个体排序；解封后的逐活动正例比例只作为 AP 随机参考和 top-k 富集分母，不能回填为预测。

N1 为仅使用活动事实 S 的低容量概率模型，不使用任何家庭 X、家庭 ID 或活动 ID。模型形式、正则与失败回退在 D 开发、R 选择后冻结。同一测试活动内 N1 分数必须相同，因此其 AP 只反映并列基准，不得宣称识别高响应家庭。N1 的作用是区分“知道活动层基率”与“具有个体响应信号”。

B1 为固定业务排序：有历史已结束活动兑换者优先 → 历史活动兑换率较高优先 → R 更小优先 → F 更高优先 → M 更高优先。无历史活动者保留独立缺失标志；剩余同分用固定家庭—活动哈希打破。B1 是排序分数，不计算 Brier、log loss 或校准。

不得按 T 表现修改 N0/N1/B1。仅 R/F/M 排序和增加目标品类匹配的规则可作为预设敏感性结果，不能替换主 B1。

产出：《E1a 基准与规则卡》及 D/R 结果。验收：N0/N1 不使用个体结果，B1 不伪装概率，三者均不读取 T。

### 步骤 16：落实 Logistic B2 与 CatBoost B3

两者预测 Y1，使用同一结构化 X/S 与缺失标志。Logistic 对数值预处理、类别编码只在 D 拟合；CatBoost 使用冻结的类别与未知值规则。主模型不使用家庭 ID 或活动 ID。

为防止小数据上无限调参，预设有限搜索：

| 方法 | 开发候选 | 选择规则 |
|---|---|---|
| B2 | L2 Logistic；正则强度 C 为 0.01、0.1、1、10；不默认重加权类别 | D 内按时间留出，以活动宏 AP 选择；差不超过 0.0001 时选更强正则 |
| B3 | 深度 3、5；学习率 0.03、0.1；最多 1,000 轮；历史验证早停耐心 50 轮 | D 内时间验证选择；同分优先较浅模型；最终轮数冻结 |

建议 D 内开发顺序：以 27、28、29 的标签训练，评价 1、2、3、4、5、6、7 的输入与结果；前者最晚结束 334，后者最早开始 346。此子划分用于方法开发，不宣称独立活动推断有效。若有效正例不足无法拟合，停止该候选并记录，不能转用 T 补样本。

最终基础 B2/B3 用全部 D 训练；R 用于终选和一维校准，R 之后不再根据 T 更新。为保证校准数据独立，主版本不把 R 回并训练。若希望 D/R 合并训练须另设时间外折的校准方案，并在冻结前替换协议。

校准默认比较不校准与 Platt 校准，由 R 的活动等权宏 Brier 确定，保留各自结果。校准映射斜率不大于 0、R 缺少两类结果、完全分离或无法收敛时，一律回退无校准并说明。P1 使用相同 R 校准机会，不能只为传统方法或只为 Persona 提供测试标签校准；在 R 上选择校准只属于开发，不能当作独立最终验证结果。

产出：《E1a 方法与训练记录》，包括 N1/B2/B3 的训练活动、实际标签数量、预处理、候选数、选择依据、校准来源、最终配置及失败。验收：强表格基线已充分但有限地开发，模型选择不触及 T。

### 步骤 17：落实 P1 与 E1b 的同模型直接对照

P1 输入固定的家庭 Persona 与活动事实卡，要求给出活动期至少一次有效兑换的 0—1 声明概率。提示注明只依据给定事实、未知信息保留未知。每次调用不携带其他测试家庭的结果，不跨活动积累隐含标签记忆。

输出保存概率、解析状态、运行配置和原始响应。可保存简短理由供案例，但不把理由当真人心理证据。每家庭—活动的正式调用次数由步骤 19 判断的确定性或随机路径冻结；任何重复都不是额外真人样本。

P1 原始声明概率与冻结的 R 校准后概率分别报告。所有主方法的 AP 使用未校准主分数；Brier/log loss 使用 R 已选定的概率版本，并附原始概率结果。单调校准不会制造排序增益，不用测试结果决定翻转分数。

E1b 使用三个同基础模型直接对照：L0 只接收活动 S；L1 接收完整 X/S 的中性结构化事实；L2 接收与 P1 完全相同事实、字段顺序和数值精度的 Persona 文本，但不进入 Survey Agent 工作流。L1 与 L2 的任务事件、输出 schema、模型版本和生成参数必须与 P1 一致。不得为了让某条件表现更好而独立改写事件定义或加入额外示例。

L0 检验客户事实整体价值；`L2-L1` 检验 Persona 表达；`P1-L2` 检验 Agent 工作流。若实际渲染后 L2 与 P1 的模型消息完全相同，应合并两者并明确无法识别 Agent 工作流，而不是保留两个名称制造差异。

产出：《任务提示与输出规范》《L0/L1/L2/P1 消息差异表》。验收：四种条件的每项事实和唯一差异可逐字段复核；P1 不独享信息；原始与校准概率可区分。

### 步骤 18：落实 E1b 的关联、丰富度与模型复核

| 条件 | 具体怎么做 | 固定什么 | 可以解释什么 |
|---|---|---|---|
| P2 错配 Persona | 同活动内把另一家庭的整套 X 转给原家庭，并为替代家庭重算活动匹配字段；原家庭 Y 保持不动 | 模型、S、任务、输出 | 正确家庭—事实关联是否重要 |
| P3 精简 Persona | 仅保留冻结的 R/F/M 基本行为与同一活动事实 S | 家庭、活动、模型 | 丰富行为信息相对基本画像是否有贡献 |
| P4 第二模型 | 在 L1/L2/P1/P2/P3 的同一输入和任务上更换预设基础模型 | X/S、模板、指标 | 主要机制方向是否依赖单一模型 |

P2 不能只在同群体内交换。先以 X 形成不同频率/匹配群体，再在活动内做固定种子的置换，避免给家庭分配回自己的事实，并尽可能使来源群体不同。保持整个来源记录内部一致，不拼凑各家庭字段。记录跨群体错配比例；活动太小或只有一个群体无法做到时，报告该对照的可识别限制，不删原家庭。

P2/P3 共用 E1a 的同一评价家庭，不能为各条件另抽一组“代表性用户”。P4 原则上复核 L1/L2/P1/P2/P3 的全部关键对比；若资源限制只能使用子集，该子集必须在冻结前仅按 X/S 固定，所有相关条件同跑，结论限定于该子集。

等义模板只作为预设敏感性条件，不再建立新的实验编号。若执行，保持事实、字段顺序、模型、输出事件和 schema 不变，并与 P1 在同一冻结集合上成对运行。

产出：《E1b 方法矩阵与输入差异表》。验收：L0/L1/L2/P1/P2/P3/P4 的每个差异有单一解释目标，调用次数与失败处理可比较。

### 步骤 19：技术试跑、生成稳定性与预算

先在 D 的约 20 条边界记录试跑：核对任务输入、原始概率、格式、超时、日志与方法身份。合法概率需是有限数值且处于 [0,1]；不能把非法值自动当作未兑换。

随后在 R 的固定约 100 条家庭—活动上做技术区分度与随机性检查，按活动和 X 分群覆盖；单活动不足时使用其全部可用记录，记录实际规模。先判断配置是否真实随机：温度为 0、固定 seed 且相同运行环境下完全相同的调用不得计作独立重复。

确定性路径：主配置每条只生成一次；可用少量完全复现检查验证日志和运行环境，但不把重复文件当作新增证据。随机路径：预先固定至少 3 个不同 seed，并让 L0/L1/L2/P1/P2/P3 使用相同 seed 集合；主分数为固定 seed 的平均。对各活动检查 seed 间 Spearman 和 top-30% 名单 Jaccard，最小值均须不低于 0.80；未达标时只可在 T 前统一增加固定 seed 数或声明方法不稳定，不能挑最好 seed。

无论哪条路径，P1 在 R 必须通过最低技术区分度：合法分数不能全相同；每个样本数不少于 20 条的 R 活动中至少出现 3 个不同合法分数；跨全部检查记录时，任一单一分数不得占 90% 以上。阈值只判断分数是否退化，不保证预测准确。若未通过，可仅在 D/R 修改提示、概率刻度或生成配置并重新完整检查；达到冻结期限仍失败时，停止正式 P1 T 预测并将技术不可用作为结果，不能通过读取 T 调整。

超时或非法格式最多重试 2 次；重试仍失败的单次调用使用 D/R 冻结总体兑换率回退，随后按固定重复数平均，不能减少失败家庭的分母。报告原始失败率、重试恢复率、最终合法率、回退率及群体集中失败；回退不计为合法生成。最终合法率低于 99% 时先判断技术可用性，不直接进入大规模推断。

随机路径的正式主分数使用全部预设 seed 的平均，不再从中挑“主批次”；seed 重复不作为独立真人样本。正式调用预算为各条件的家庭—活动数乘以冻结重复数，再加试跑和最多两次技术重试。L0 只有 S，可按活动与冻结 seed 生成并广播，不虚报为逐户模拟。

用试跑实测每次时长、输入/输出量和计费单价，填写最低预算、最大预算、预计时长与停止上限；本地模型记录设备和运行时间。没有服务价目与试跑计量之前，不虚构费用。

产出：《区分度、稳定性和成本报告》。验收：合法率不低于 99%，P1 通过最低区分度；随机路径另通过稳定性门槛；所有必需条件有可完成预算。未通过区分度时不得进入 T。

## 8. 阶段五：冻结与正式预测

### 步骤 20：签署冻结记录

至少固定以下内容：E1/E1a/E1b 层级；N0/N1/B1/B2/B3/P1/L0/L1/L2/P2/P3/P4 身份；原始数据版本；D/R/T 活动 ID；家庭权限；纳入与异常规则；字段与词表；活动事实；提示、模型、校准及 seed；确定性或随机路径及重复数；失败回退；B1 优先级；主标签与主输出；AP/Brier 与机制比较族；top-k 和同分处理；依赖结构与区间范围；E2/E3 是否执行；成本上限；预测封存与解封条件。

新增或修改本手册默认方案时，在冻结表逐项记录原方案、新方案、原因以及是否接触测试结果。至少完成一次由方案审核者逐项复核。

验收：不存在“跑完看哪项好再决定”的空位；所有 T 模板、模型、方法 ID 和数据口径能从冻结版本恢复。机器预测合同必须将 E1a、E1b 作为两个完整预测集枚举；父级 E1 不另登记预测制品。

### 步骤 21：生成 E1a 与 E1b 的正式预测

操作顺序：导出白名单 X/S → 校验每方法记录数量 → 运行 E1a 的 N0/N1/B1/B2/B3/P1 → 运行 E1b 的 L0/L1/L2/P2/P3/P4 → 按预设规则重试和回退 → 导出完整预测表 → 完成不依赖 Y 的质检 → 分别封存 E1a 与 E1b。

预测表一行至少包含：家庭—活动键、方法、配置、重复编号、原始分数、校准分数、最终主分数、解析状态、重试、回退、成本/时间、批次和输入版本。不得仅保存汇总平均，丢失失败和原始重复。

不依赖 Y 的质检：输入与预测一一对应、分数范围合法、数量不缺、方法使用同一评价集合、同分处理一致、日志可追溯、无未来字段。此时不算 AP、不看预测高分组的真实响应。

产出：《E1a/E1b 预测封存包》及校验值。验收：两个子实验的全部必需方法已产生冻结预测，且制品集合与注册合同全等，之后才可按 E2 决定开放适配结果或最终结果。

## 9. 阶段六：可选 E2，回溯式当前活动标签预算

### 步骤 22：先判断预算是否可执行

本实验问的是：完整活动结束后，若只开放部分家庭标签，冻结的 Persona 分数对传统模型是否仍有附加价值。没有先试投后正式投放的时间证据时，不叫真实上线前试投。

先在不看 Y 的情况下统计每活动适配家庭数及最终评价数。既有最大参与规模约 276 户，20% 适配池通常约 55 户；实际全局家庭划分会使比例波动。原 100/250/500/1000 预算大多不可用，不能从最终评价池补样本。

本手册建议将预算修订为 n=0、10、20、40，并在冻结表记录它对蓝图旧预算的修订；不是已执行的新结果。每 n 中训练/验证标签均计入预算。每活动适配池不足 n 时标不可执行，不改变该活动 E1 的归属。

如果所有非零预算都没有足够可运行活动，按冻结决定不做 E2；若仅少量活动可执行，仅报告探索性案例，不制造完整学习曲线。

### 步骤 23：固定嵌套标签和适配方法

适配家庭按与 Y 无关的固定哈希顺序建立训练/验证子池，再分别嵌套取前 floor(0.8×n) 与 n−floor(0.8×n) 个，形成总计 n 的预算。子池权限全局固定，保证小预算验证家庭不会在大预算变成训练家庭；任一子池不足时该活动预算记不可执行。此细化替代“直接取前 n 后再按 80%/20% 切分”，避免验证家庭权限随 n 改变。

E1a 与 E1b 全部预测必须先封存。然后由保管方只开放当前预算的适配标签；最终评价 Y 继续封存。模型、提示和重复不得因适配结果回改 E1a/E1b。

由于 n 很小，默认不用每活动从头训练高容量树模型。采用同一低容量适配框架作为四个条件的共同外层：

| 条件 | 具体输入与用途 |
|---|---|
| E2-0 | 冻结历史 B3，不适配，作为历史参照 |
| E2-1 | 当前预算适配历史 B3 分数的一维 Logistic 校准器 |
| E2-2 | 相同校准器框架，加入冻结 P1 分数 |
| E2-3 | 相同框架，加入冻结 B2 分数，与 E2-2 同样只增加一个预测源；B1 额外融合可作次要对照 |

在 n=0 时只报告 E2-0；E2-1/E2-2/E2-3 仅在 n>0 且满足拟合条件时运行，不能把无标签回退重复登记成三个适配模型。

外层正则及特征转换用 D/R 的模拟小预算任务预先确定，各预算不另做大量调参。训练标签只有一种类别、拟合失败或完全分离时，回退到已固定历史版本并报告；不能重新抽标签直到同时有正负例。小验证集仅作流程与失效检查，不用于搜索多个候选模型。

如果要采用蓝图原先的“CatBoost 加 Persona 特征”版本，应额外运行相同架构、训练轮数和标签预算的有/无 Persona 成对模型；样本不足的局限需明确，不以不稳定高容量适配作为唯一结论。

### 步骤 24：封存 E2 预测并评价

对每个 n 在相同最终评价家庭上预测并封存；完成所有预算后再解封 Y。同时报告各 n 可用活动清单，以及 n=10/20/40 都可用的共同活动子集曲线，防止活动组成变化造成假提升。

主要增益是 E2-2 相对 E2-1 的配对差；E2-3 用于检验是否超过传统多模型融合。概率与排序分开，样本少时报告效应与局限，不默认作确认性检验。

产出：《E2 标签使用账本》《共同活动学习曲线》《适配失败记录》。验收：不存在免费额外验证标签、不存在全局权限交叉、不存在结果驱动重抽样。

## 10. 阶段七：解封、统计与机制分析

### 步骤 25：一次性解封

解封前核对：必需 E1a/E1b 已封存；执行 E2 时所有预算预测也已封存；冻结记录完整；方法数量与评价集合一致；所有异常处理已决定。

保管方登记解封日期、预测版本与标签版本，之后才开放 T 的逐户 Y 和活动基率。发现错误先保存原评价，不覆盖原结果。

### 步骤 26：按固定顺序评价

| 顺序 | 指标与处理 | 目的 |
|---|---|---|
| 1 | 每活动 N、独立家庭、Y1 基率、有效标签覆盖 | 说明评价支持度 |
| 2 | E1a 中 P1 相对 N0/N1 的 AP、Brier、log loss 与 top-k 富集 | 层次 1：是否存在外部预测信号 |
| 3 | E1a 中 P1−B1/B2/B3 的每活动 AP 与等权宏平均 | 层次 2：相对传统方法竞争力 |
| 4 | 逐家庭—活动汇总 AP 与加权逐活动指标分别注明 | 防止混淆合并池与活动平均 |
| 5 | N0/N1/P1/B2/B3 的 Brier、log loss、校准图 | 概率准确性；B1 不参加 |
| 6 | E1b 的 L1−L0、L2−L1、P1−L2、P1−P2、P1−P3 及 P4 方向复核 | 层次 3：Persona 增量来源 |
| 7 | 失败、回退、调用稳定性、耗时与成本 | 可实施性 |
| 8 | 预设 Y2/Y3 或 E2/E3 扩展 | 补充，不能改换主标签 |

AP 采用 Average Precision 的固定定义，不换成梯形 PR 曲线面积。逐活动宏平均分母在所有方法间相同。top-k 人数为 floor(k×N)，所有方法按同一家庭—活动哈希打破并列；N 太小时展示实际选择人数，人数为 0 则记不可算。

log loss 的概率固定裁剪为 [0.000001,0.999999]；Brier 使用实际合法概率，不按测试拟合校准。校准图采用固定五个等宽概率区间，小样本箱显示 N；校准截距/斜率可能因低基率或分离无法稳定估计，标为不可估计，不强行给精确值。

### 步骤 27：区间、比较族和结论强度

E1a 分成两个不可互换的比较族。层次 1 的基础效度族是 P1 相对 N0/N1 的两项 AP 差；若作该条件范围内的判断，使用 Bonferroni 97.5% 双侧同时区间。层次 2 的竞争力族是 P1 相对 B1/B2/B3 的三项 AP 差，使用 Bonferroni 98.3333% 双侧同时区间；三项下界均大于 0 才支持该范围内优于全部预设传统基线。

当前默认 T 仅一个重叠连通块，因此不生成伪独立活动区间。主报告逐活动差值、宏平均差、正负方向活动数、基率和异质性；方向一致也不能替代独立重复。

按既定补充，另做固定这批活动的家庭聚类配对 Bootstrap：抽中某家庭时，其全部测试活动记录一起进入，所有方法使用同一抽样，10,000 次，不重训、不重新校准。报告 95% 描述性区间；AP 三主差值如作该条件范围内的比较判断，仍给 Bonferroni 98.3333% 区间，但标题须写“固定测试活动、家庭聚类条件区间”。

家庭区间仍依赖家庭可交换性，不能消除共同活动或门店冲击，也不代表新活动的不确定性。宏 AP 的活动集合固定为原始评价中 AP 可识别的活动；某次重采样导致集合中任一活动无正例时，该次宏 AP 区间抽样整体记无效，不能只删掉该活动重算分母。记录 10,000 次尝试中的无效比例；预设无效比例超过 5% 时不提供宏 AP Bootstrap 区间，改报原始逐活动差值。5% 是诊断停止阈值，不证明未触发时区间必然有效。

Brier 比较族为 P1 对 N0/N1/B2/B3；若在可说明的条件范围内报告检验，采用 Holm 校正，并列明原始与校正结果。E1b 的五项主要机制对比另成一族；若作显著性判断同样使用 Holm 校正，不能以其中任意一项有利结果概括为 Persona 全面有效。P4 用于方向复核，不与主模型结果合并增加样本量。

### 步骤 28：在四层框架下分析当前实施的层次 1—3

先回答 E1a 层次 1，再回答 E1a 层次 2，最后回答 E1b 层次 3。若 P1 不胜过 N0/N1，停止“优于传统方法”的概括，但仍完整报告 B1/B2/B3。若 P1 胜过 N0/N1 而不胜过 B3，只能称有预测信号但没有显示优于强表格模型。

E1b 中，L1 优于 L0 只说明客户信息有用；L2 优于 L1 才支持 Persona 表达增益；P1 优于 L2 才支持 Agent 工作流增益；P1 优于 P2 才支持正确客户—画像关联；P1 优于 P3 才支持丰富行为字段。P1 仅优于 L0 不能写成 Persona 或 Agent 有效。第二模型方向反转时，所有机制结论限定为当前基础模型。

对概率偏高、低频家庭误差、目标品类匹配高但不兑换、模型更换后方向反转、集中调用失败等现象，按预设群体和诊断检查。只能说记录行为与模型结果的关系，不能用生成解释证明家庭真实动机。

案例选择依据逐记录 Brier 损失，以 P1 与 B3 同时低损失、同时高损失、P1 损失低于 B3、B3 损失低于 P1 四类展示；前两类按两者平均损失从低/高选取，后两类按损失差绝对值排序，最多各 3 条，同分按固定哈希打破并隐去家庭标识。案例可交叠，需注明；不临时用某个分类阈值定义“正确”。案例属于事后解释，不替代统计结果，四类都保留。

产出：《主评价表》《机制与失败分析》。验收：负结果、NA、回退和不稳定都出现在论文材料中。

## 11. 可选 E3：Hillstrom 随机化策略压力测试

本实验独立于 Dunnhumby，只有在主线可交付且资源允许时执行，不作为主线未胜出的补救数据。

### 步骤 29：获取、审计和独立冻结

核实数据来源、邮件随机分配说明、实际处理概率 e、重复行、结果窗口与缺失。仅观察三处理样本比例接近 1/3 不足以证明随机；来源证据不足时，不做因果 IPS 主张。

使用新蓝图而非历史冷启动协议：按处理分层 D/R/T=20%/40%/40%，seed=20261009；D/R 的 M/W/0 标签均可用于训练，T 标签封存。客户实际分配处理不进入 Persona，只有允许的投放前字段与待评估动作进入模型。

### 步骤 30：固定三动作预测和策略

每方法对每位 T 客户分别给出发送男装邮件 M、女装邮件 W、无邮件 0 的两周访问分数。无邮件可能自然访问，不能将其预测固定为 0。

选预测更好的邮件，计算其相对无邮件的分数差；按差值排序，固定给 floor(0.30×N_T) 人发选定邮件，其余不发。所有方法主比较为同一客户级策略粒度，10%/20% 为次要预算。

规则对照不伪装成增量概率：先按男/女装既往购买选择匹配邮件，再按固定品类/RFM 排序；两类同样匹配或同样未买时使用冻结默认邮件与哈希顺序。另列仅正差值且最多覆盖 30% 的策略，不能混入固定 30% 主比较。

### 步骤 31：封存策略并评价

每方法保存完整 T 的三动作分数、最终动作与覆盖。解封后在完整 T 上计算 IPS：实际处理与策略动作一致时，以实际结果除以对应 e；不一致贡献为 0；对全部 T 客户平均。不能仅保留一致行再改变分母。

主结果为 visit，conversion/spend 次要。配对差用同客户抽样，并按核实的随机分配层与处理保持层人数重采样 10,000 次。SNIPS 作辅助；同时报告一致样本数、ESS、实际覆盖及动作分布。

P1 对规则、Logistic、CatBoost 三差值另成 Bonferroni 比较族；相对不发邮件单列。有限邮件场景的优势不能证明 Dunnhumby 优惠券的因果增量，访问率也不能称利润。

产出：《随机化证据》《独立冻结包》《预算—策略价值表》。验收：随机机制与概率有来源支持，动作与覆盖在 T 结果可见前固定。

### 步骤 32：处理异常、补跑和协议变更

每次异常先登记发现阶段、影响范围、原因、已看过的结果、修复方案及原始版本，不直接覆盖已封存输出。

| 情况 | 处理方式 | 结果地位 |
|---|---|---|
| 冻结前发现字段错误或预算不足 | 统一修正全部方法，重做受影响开发与核验，重新冻结 | 可作为正式起点 |
| 冻结后、解封前出现调用失败 | 仅按已预设重试与回退处理；不可依据分数好坏额外挑批次 | 保持冻结主版本 |
| 解封后发现标签连接或指标实现错误 | 保留原结果，给出一致修正规则、影响数量与更正前后表；不能根据某方法获益决定是否更正 | 明确标注协议后的技术更正及其影响 |
| 解封后才发现输入含未来信息 | 原主结果认定受污染；修复后结果不能重新称独立盲测，需新增未参与开发的评价或降为探索性 | 不支持原先确认性主张 |
| 解封后想换提示、模型、群体或标签 | 单独保存原主结果，新增分析与来源记录；不覆盖主结果 | 探索分析 |
| 扩展资源不足 | 报告未执行及原因，保留已固定 E1 评价集合；不能仅因表现不利删对照 | 论文范围按实际交付说明 |

产出：《异常与变更账本》。验收：任何更正都能追溯，论文的主结果与事后分析明确标识。

| P1 胜过规则，未胜过 B3 | 相比简单规则有优势，未显示优于强表格模型 | 优于传统营销评估方法整体 |
| AP 更好但 Brier 更差 | 排序改善、声明概率失准，需要校准 | 响应概率更准确 |
| P1 与 N0/N1 相近 | 未识别出可用的外部预测信号 | Persona 已能预测真实响应 |
| P1 与 L1 相近 | 未识别出完整 Persona Agent 相对结构化直接 LLM 的总体增量 | Persona 或 Agent 有独特优势 |
| L2 与 L1 相近 | 未识别出 Persona 表达增量 | Persona 表达提高预测能力 |
| P1 与 L2 相近 | 未识别出 Agent 工作流增量 | Agent 工作流是优势来源 |
| P1 与 P2 相近 | 未识别出正确客户—画像关联价值 | 模型使用了正确个体画像 |
| E1a 无优势、E2 小预算有益 | 冻结 Persona 分数可能是有限标签适配的辅助信息 | 零当前活动标签预测已经优于监督方法 |
| 第二模型/模板方向反转 | 结果依赖配置，应限定结论 | 方法不依赖模型、可直接推广 |
| E3 策略价值更高 | 在该随机邮件试验和预算下支持访问率策略优势 | 优惠券 ROI 或营销利润已经提高 |
| 区间宽、样本低支持或 AP 不可识别 | 当前证据不足，明确精度与支持度 | 两方法等价或没有真实差异 |

不要求论文以 Persona 获胜结束。严谨的负结果、校准失效或配置依赖，都能回答研究问题；前提是对照完整、执行可追溯、结论与证据范围一致。
