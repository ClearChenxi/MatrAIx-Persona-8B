# E0a 历史开发活动接口检查方案

版本 v1.0；2026-10-10。状态：代码及合成夹具已准备，真实家庭读取和模型执行尚未授权、尚未发生。本方案供用户审核，不是 E1 冻结协议。

## 目标和范围

验证真实历史开发活动的投放前行为，能否按时间规则进入官方开源 Survey Agent，并得到可解析、可追溯的数值输出。没有真实结果标签，不评价准确性、校准或相对基线优劣。

拟用最早 D 活动 27，Type C，START_DAY=237、END_DAY=300，有效期含首尾共 64 天。只聚合 DAY153—236，共 84 天；DAY237 当天和之后的交易不进入 X。不读取 coupon_redempt、hh_demographic 或测试标签，也不统计测试响应率。

选择 campaign_table 中该活动的参与家庭，要求窗口内至少一条 QUANTITY>0 且 SALES_VALUE≥0 的合法购买。按 `sha256("20261010:27:{household_key}")` 升序、家庭 ID 次级排序，取前三户。样本不代表总体；无历史家庭不自动补零。若不足三户即停止，不换活动或扩大窗口。家庭和活动 ID 只保存在本地连接档案，不发送为预测特征。

每户两次，最多六次本地生成。模型为已有 Ollama `qwen3.5:9b`，版本/完整 digest 必须与方法身份记录一致；有效参数沿用已验证合成配置。首个失败停止，不重试、不补生成、不插补、不回退。固定种子不能保证跨环境完全重复。

## 表与字段口径

读取白名单仅五张表；准备前后保存全文件 SHA-256。交易文件按流扫描，先按日期和参与关系过滤，再解析购买字段；读完整文件字节用于哈希不等于使用未来交易作为输入。来源时间范围核验只检查最早 DAY 覆盖窗口起点，不能证明每户观察完整性。

| 输入 / 特征 | 来源与规则 | 缺失、精度与限制 |
|---|---|---|
| 活动类型、起止日 | campaign_desc：DESCRIPTION/CAMPAIGN/START_DAY/END_DAY | 必须唯一且与方案一致，否则停 |
| 收券关系 | campaign_table：DESCRIPTION/CAMPAIGN/household_key | Type B/C 已知整个券包；参与重复计数、集合去重 |
| 唯一券 / 商品规模 | coupon：CAMPAIGN/COUPON_UPC/PRODUCT_ID | 券—商品对去重；空 ID 或连接不全即停 |
| 品类覆盖 | product：PRODUCT_ID/COMMODITY_DESC | 空品类标 `<unknown>`；冲突商品记录即停 |
| 品类权重 | 券—商品连接后，唯一券—品类对按品类计数并归一 | 不是商品数权重；同一券可属多品类；前八品类按计数降序、名称升序，其余合并；四位小数 |
| shopping_baskets / shopping_days | transaction_data：BASKET_ID/DAY，符合窗口及正购买规则的唯一值计数 | 多商品同篮只计一篮；排除 QUANTITY≤0；不是家庭成员购物次数 |
| days_since_last_positive_purchase | 截点 237 减窗口内最近正购买 DAY | DAY236 对应 1，不是 0 |
| positive_purchase_sales_value | 窗口内正购买 SALES_VALUE 的 Decimal 累加 | 排除退货；不是净销售额；两位小数 ROUND_HALF_UP，不推断币种 |
| target_product_sales_share | 优惠券覆盖 PRODUCT_ID 的正购买金额 / 总正购买金额 | 四位小数；分母零记 unknown，不记 0 |
| target_known_category_sales_share | 优惠券已知品类集合的正购买金额 / 总正购买金额 | `<unknown>` 不当成已知品类；四位小数，分母零记 unknown |
| days_since_last_target_product_purchase | 截点减最近目标商品正购买 DAY | 窗口内无目标购买记 unknown，不记 0；不推断窗口外行为 |
| historical_redemption | 不读取兑换表 | 固定 `unknown: redemption table not accessed`，不能当零兑换率 |

购买字段仅读取 household_key/BASKET_ID/DAY/PRODUCT_ID/QUANTITY/SALES_VALUE。非有限金额/数量、正数量负金额、空购物篮或无法连接的历史商品触发停止。QUANTITY≤0 的退货/非购买不计入正购买聚合。实际来源异常若触发停止，先记录并审核规则，不为凑六次而静默删改。

活动金额、最低消费、文案、图片、心理和人口属性均未知，不补齐。本轮只提供狭义 X/S；正式 E1 的部门/品牌词表、优惠券历史和同信息基线仍由后续阶段落实。

## 执行及验收

配置为 [history-plan.json](history-plan.json)，目前 `execution_approved=false`。默认运行历史程序只展示方案，不读取家庭记录、不访问 HTTP、不调用模型。准备模式和执行模式均要求先记录用户确认、提交并推送代码、保持工作区干净和官方固定基线不变。

官方提示构建会再次按问卷 ID 查找内容。适配层仅在运行内暂时把历史问卷 ID 映射至该次准备包的任务目录，结束后恢复；不改官方源文件。合成验证已确认活动 context 和行为完整进入消息。正式运行每次再比对实际消息与预渲染消息，拒绝任务回退或属性补齐。

每次建立新的本地目录，保存 plan/config、原始文件哈希、抽样/字段档案、任务、Persona、代码/依赖/模型版本、预期与实际消息、原始请求和响应、官方产物、解析状态、失败、两次重复差、manifest 及文件校验清单。原始真实记录和日志留在被 Git 忽略的本地目录；代码、方案及不包含家庭明细的报告提交 GitHub。若只准备输入，清楚记录零次模型调用。

验收条件：三户输入时间边界正确、来源完整；每户两次消息一致；六次均合法且未截断；没有额外生成、修复或标签读取；运行前后模型指纹一致；独立证据核验通过。重复差如实报告，不要求强制为零。异常记录保留；失败不算验收通过。

通过后更新《方法身份记录》和历史验收报告，才能审核 E0a 整体是否通过。该检查不替代 E0b 的连接/观察完整性审计、后续约 20 条 D 边界试跑或 R 的多批次稳定性试跑。
