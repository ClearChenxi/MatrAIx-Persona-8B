## 2. 官方数据内容

官方用户指南说明：数据表示某零售商 2,500 个高频购物家庭两年的家庭级交易；包含这些家庭在店内的全部购买，不仅是少数商品类别；部分家庭还提供人口属性和直接营销联系历史。官方明确建议的问题包括：哪些客户消费增加或减少、哪些客户属性影响消费、直接营销是否改善客户参与度。

该数据可以观察：

> 零售企业根据客户历史行为发送优惠券或活动后，客户是否兑换、购买更多商品，或者改变商品选择。

## 3. 实际文件和字段核查

官方 ZIP 包含用户指南和 8 个 CSV 文件。实际行数和表头如下：

| 文件 | 行数（不含表头） | 主要字段 |
|---|---:|---|
| `campaign_desc.csv` | 30 | `DESCRIPTION,CAMPAIGN,START_DAY,END_DAY` |
| `campaign_table.csv` | 7,208 | `DESCRIPTION,household_key,CAMPAIGN` |
| `coupon.csv` | 124,548 | `COUPON_UPC,PRODUCT_ID,CAMPAIGN` |
| `coupon_redempt.csv` | 2,318 | `household_key,DAY,COUPON_UPC,CAMPAIGN` |
| `hh_demographic.csv` | 801 | 7 个家庭属性字段和 `household_key` |
| `product.csv` | 92,353 | 部门、商品类别、子类别、品牌、规格 |
| `transaction_data.csv` | 2,595,732 | 家庭、购物篮、日期、商品、数量、销售额、折扣、门店、时间 |
| `causal_data.csv` | 36,786,524 | 商品、门店、周、店内展示 `display`、宣传单 `mailer` |

### 关键表的作用

#### 客户/Persona 原料

`hh_demographic.csv` 提供部分家庭的匿名化属性。字段名是泛化的 `classification_1` 到 `classification_5` 等，官方说明这些值具有有序性，但不是明确的年龄、收入或职业标签。因此它可以作为人口背景变量，却不能把 `Group2` 自行解释成“中等收入”。

`transaction_data.csv` 是主要行为来源。可以按活动开始前的时间窗口聚合：

- 购买次数和购物篮次数；
- 最近购买天数；
- 总消费和平均客单价；
- 商品部门和类别偏好；
- 品牌偏好；
- 优惠券折扣和忠诚卡折扣使用率；
- 购买时间和门店活动习惯。

这些字段可以构建一个**交易行为 Persona**，但不能直接推断消费者的性格、动机或真实价格观。

#### 营销方案/处理

`campaign_table.csv` 记录家庭参与了哪些活动；`campaign_desc.csv` 记录活动类型和起止日期；`coupon.csv` 记录活动中的优惠券以及可兑换商品；`causal_data.csv` 记录商品是否出现在店内展示或宣传单中。

因此它有明确的营销处理和活动上下文，但它没有广告正文、图片、短信文案或消费者主观理由。

还要注意优惠券分配的具体缺口：官方用户指南说明，TypeA 活动的 `coupon.csv` 是候选优惠券池，客户实际收到的 16 张优惠券并未在数据中逐客户记录，而且这些优惠券是基于客户过去购买行为选择的；TypeB 和 TypeC 活动则是参与客户收到该活动的全部优惠券。因此，不能把 `coupon.csv` 中的每一张 TypeA 优惠券都当作每个客户真实收到的处理，也不能直接对单张 TypeA 优惠券做无偏的因果比较。

#### 真实结果

`coupon_redempt.csv` 记录优惠券兑换；`transaction_data.csv` 记录之后的购买、金额、数量、商品和折扣。可以构造：

- 是否兑换优惠券；
- 活动期间是否购买目标商品或类别；
- 活动期间消费金额变化；
- 购买数量变化；
- 是否购买以前没有购买过的商品类别。

## 4. 数据可表示的营销场景

数据可用于如下离线分析：

> **在零售活动或优惠券投放前，根据客户过去的交易行为构建 Persona，让 Persona agent 评估不同客户群体对活动的可能响应，并与真实兑换和交易记录比较。**

例如，在活动开始前使用家庭过去 8 至 12 周的交易数据生成：

```text
高频购买家庭；近期购买下降；常买冷冻食品；优惠券使用率较高；偏好自有品牌
```

然后让 agent 判断该家庭对某类优惠券的可能响应。活动结束后，用真实的兑换、购买金额和商品购买记录验证。

如果使用 Persona 方法，这些字段分别提供：

1. Persona cohort：可以按交易行为构建不同客户群体；
2. Commerce task：输入优惠券/活动情境并要求给出响应；
3. External validation：用之后真实交易而不是语言自然度作为标尺。

## 5. 可观察的结果与问题

Dunnhumby 可以用于考察：

- 交易行为 Persona 是否能预测优惠券兑换；
- Persona agent 是否能识别活动期间更可能增加购买的客户群体；
- 不同客户分群或预测方法对兑换和购买的区分能力；
- 促销、店内展示和宣传单曝光是否与购买变化相关；
- 不同客户群体对优惠券活动的响应方向是否不同。

## 6. 它不能直接证明什么

需要特别注意四个限制：

1. **不是严格的消费者意愿调查。** 没有“你是否愿意购买”和“为什么”的直接问卷答案，只有兑换和购买行为。
2. **不能直接声称因果效果。** 官方数据指南说可以研究直接营销影响，但数据中家庭参与活动的具体分配机制仍需审计；不能未经说明地把观察到的差异写成个体因果效应。
3. **不是多个价格方案的实验。** 商品和优惠券有类别、活动和兑换信息，但没有完整的价格实验设计，也没有广告文案语义。
4. **人口属性不够直观。** `classification_*` 是匿名有序编码，不能擅自翻译成年龄、收入或教育。

## 7. 数据适配性与限制

| 维度 | 判断 |
|---|---|
| 真实营销场景 | 高 |
| 交易行为 Persona | 高 |
| 优惠券/活动建模 | 高 |
| 多价格/文案概念测试 | 低到中 |
| 严格随机因果评估 | 未确认，需谨慎 |
| MatrAIx 营销任务匹配 | 中高 |
| 数据处理规模 | 多表；最大单表约 3,679 万行 |
| 授权 | 官方允许研究/非商业使用，但不是开放许可证；不可直接再分发原始数据 |

该数据记录真实交易和优惠券响应，不是完整的消费者概念测试或价格实验；活动分配机制不明时不支持严格因果解释。
